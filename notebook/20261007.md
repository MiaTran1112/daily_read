## dbt Orchestration with Fivetran

**Article:** [I rebuilt my ingestion pipeline with zero infrastructure: Part 2 — dbt, run by Fivetran](https://markphammm.substack.com/p/i-rebuilt-my-ingestion-pipeline-with-02e)  

**Core idea:** Fivetran can run dbt Core after ingestion, removing the need to operate a separate scheduler for a simple “sync → transform” pipeline.

### 1. Architecture
`Neon Postgres → Fivetran CDC → Snowflake landing → TRANSFORM → SERVE`

dbt handles SQL transformations and dependency ordering; Snowflake executes the SQL.

### 2. Execution and configuration
- Fivetran clones the Git repository using a read-only SSH deploy key.
- It generates `profiles.yml` from existing destination credentials.
- Scheduled runs use `FIVETRAN_USER` / `FIVETRAN_ROLE`; local dbt credentials are separate.
- Jobs and schedules live in root-level `deployment.yml`.

### 3. Scheduling and dependencies
- **Integrated schedule:** starts transformations after a connection finishes syncing. Use its system connection ID.
- **Cron schedule:** runs at a fixed time.
- `+tag:daily` selects daily models **and their upstream dependencies**.

### 4. Critical failure checks
Verify the exact landing schema name, destination-role write permissions, and model ownership. Confirm the integrated job shows its linked connection—manual success alone does not verify automatic triggering.

### 5. Main lessons
Managed orchestration suits straightforward ingestion-plus-dbt workflows. Custom Python, API calls, or conditional steps need broader orchestration. Successful execution also does not guarantee correct data: this demo lacks dbt tests.
