### Mark Pham: I rebuilt my ingestion pipeline with zero infrastructure: Part 2 - dbt, run by Fivetran (https://substack.com/home/post/p-215043072)

Revisit from part 1:
- WAL: write-ahead log (conceptually an activity log)
    - Postgres needs this for crash recovery and physical replication.
    - "Say the WAL events are numbered 100 through 105 and Fivetran has consumed through 102. The slot records that. Next sync, Fivetran reconnects and Postgres hands it 103 onward. Just as importantly, Postgres will not discard WAL that the slot still needs, so Fivetran can be offline for a while without losing data." 
    - 'pgoutput': Postgres’ built-in logical decoding plugin and the one Fivetran uses.

- publication vs slot in fivetran: (read more on Fivetran documentation https://fivetran.com/docs/connectors/databases/postgresql/setup-guide)

- dbt:

- 3 main things:
    - **dbt Core** is the free open-source CLI.
    - **dbt Cloud** is dbt Labs’ paid hosted product with a scheduler, an IDE, and a UI. Fivetran
    - **Transformations for dbt Core** is a third thing: Fivetran runs dbt Core for you, on their infrastructure, from your Git repo.

- Every project sync Fivetran:
    1. Clones your repository over SSH using a deploy key you install
    2. Generates a profiles.yml from the Snowflake destination credentials you already entered in part 1
    3. Reads deployment.yml from your repo root and creates or updates the jobs it finds
    4. Runs those jobs on their schedules, capturing the dbt output into a run log
