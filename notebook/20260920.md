1. Postgres WAL / logical replication
- wal_level = logical → enables row-level logical changes for external CDC tools.
- Publication = WHAT tables/events to capture.
- Replication slot = WHERE the connector is / its bookmark.
- 'pgoutput' = built-in Postgres plugin that decodes WAL changes.
- Abandoned replication slots can cause WAL/storage to grow indefinitely.

2. Primary keys
- CDC needs a way to identify rows for updates/deletes.
- No PK → REPLICA IDENTITY FULL logs the entire old row.
- More WAL → more overhead.
- Production preference: proper primary keys.

3. Snowflake set up
- Use a dedicated service user/role, not ACCOUNTADMIN.
- Dedicated warehouse isolates pipeline compute/cost.
- Key-pair authentication:
    - public key → Snowflake
    - private key → Fivetran
- Separate keys per service → easier independent rotation.

4. fivetran sync
- Initial sync = historical snapshot of Postgres.
- After initial sync = incremental changes from WAL.
- Fivetran adds metadata such as:
    - '_FIVETRAN_ID'
    - '_FIVETRAN_SYNCED'
    - '_FIVETRAN_DELETED'
